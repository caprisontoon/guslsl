# 강냉이 레이스

투네이션 **투네랜드**의 미니게임입니다. 강냉이를 걸고 구슬 레이스를 돌려,
1등으로 결승선에 들어온 구슬에 적힌 상품을 받습니다. 당첨왕·럭키픽과 마찬가지로
강냉이 소진 창구 역할을 합니다.

- 게임 화면: `index.html`
- 관리자 화면: `admin.html`
- 백엔드 연동 방법: [INTEGRATION.md](./INTEGRATION.md)
- API 계약: [server/openapi.yaml](./server/openapi.yaml)
- 서버 구현 명세: [server/SERVER_SPEC.md](./server/SERVER_SPEC.md)
- 테이블 DDL: [server/schema.sql](./server/schema.sql)

## 게임 방식

1. 도전하기를 누르면 **참가비만큼 강냉이가 즉시 차감**됩니다.
2. 서버가 관리자 설정 확률대로 구슬 구성을 만들고(꽝 63%면 꽝 63개), 그중 하나를
   균등 추첨해 이번 판의 당첨 상품을 정합니다.
3. 서버는 미리 계산해 둔 **시드**로 어느 칸이 1등할지 이미 알고 있습니다. 그 칸에
   뽑힌 상품을 올리고, 나머지 칸을 분포에 맞춰 채워 클라이언트에 내려줍니다.
4. 구슬에는 **상품 이름이 그대로 보입니다.** 상품마다 색이 달라서 어떤 구슬이 값진지
   한눈에 보이고, 꽝은 회색으로 표시됩니다.
5. 1등이 들어오면 그 구슬의 상품이 당첨됩니다. 꽝이면 기본 혜택 강냉이를 지급합니다.

## 구슬에 상품을 다 보여줘도 안전한 이유

보통은 화면에 답이 보이면 브라우저를 조작해 유리한 값을 신고할 수 있습니다. 여기서는
**서버가 답을 이미 알고 있고 정산에 클라이언트 입력을 쓰지 않기 때문에** 조작할 게
없습니다.

물리 엔진이 결정적이라 가능한 구조입니다. `(시드, 구슬 수, 맵)` 이 같으면 언제 어디서
돌려도 같은 칸이 1등합니다. 브라우저마다 다른 wasm 빌드(SIMD / 스칼라)를 쓰는데
둘의 결과도 일치하는 것을 확인했습니다.

```
오프라인 배치  yarn seeds 100 5000 0   ->  (시드, 1등 칸) 표를 만들어 DB 에 적재
라운드 열기    시드 한 줄을 꺼내 1등 칸에 뽑은 상품을 올린다 -> { seed, labels } 전달
클라이언트     그 시드로 레이스를 재생한다 -> 서버가 아는 칸이 1등한다
정산           서버가 저장해 둔 값으로 판정한다. 클라이언트에게 묻지 않는다
```

백엔드가 물리 엔진을 돌릴 필요는 없습니다. 시드 표만 미리 채워두면 됩니다.

클라이언트가 보고하는 "화면에서 1등한 칸"은 판정에 쓰이지 않고, 서버가 아는 값과
다르면 **재생 불일치**로 기록합니다. 이 값이 0 이 아니면 결정성이 깨진 것이므로
바로 드러납니다.

## 확률 검증

```shell
yarn verify:odds        # 환산 정확도 + 추첨 분포 + 재생 결정성
```

세 가지를 봅니다.

| 검증 | 내용 | 결과 |
|---|---|---|
| 환산 | 설정 확률(%)이 구슬 개수로 정확히 떨어지는가 | 오차 0.00%p |
| 추첨 | 그 구성에서 균등 추첨한 분포가 설정과 같은가 | 20만 판, 카이제곱 2.82 (기준 20.52) |
| 재생 | 같은 시드가 항상 같은 1등 칸을 내는가 | 시드 60개 전부 재현 |

확률 해상도는 관리자의 **구슬 수** 설정이 정합니다. 100개면 1% 단위, 200개면 0.5%
단위까지 오차 없이 표현되고, 표현할 수 없는 확률은 관리자 화면이 경고합니다.

## 관리자 기능

- **상품 목록 / 생성** — 상품 이름, 아이템 종류(강냉이·인벤토리·캐시), 지급값,
  강냉이 환산값, 당첨 확률, 당첨 인원(0이면 무제한), 노출·숨김
- **확률 설정** — 참가비, 꽝 기본 혜택, 구슬 수, 기본 맵, 상품별 확률.
  설정 확률과 실제 확률을 나란히 보여주고 한 판 기대 수지를 계산합니다.
  적용 시점은 즉시 또는 예약을 고를 수 있습니다.
- **확률 변경 이력** — 변경 시각, 적용 방식, 확률 구성, 사유
- **통계** — 일자별 도전·당첨·꽝 집계, 상품별 당첨 횟수

당첨 인원이 소진된 상품은 자동으로 필드에서 빠지고, 그 확률은 꽝으로 넘어갑니다.
